# Robot VLM Workflow Benchmark

This project builds and evaluates visual-language-model (VLM) question-answering benchmarks for robot pick/place workflows. It focuses on egocentric and multi-view robot videos, converting annotated action segments into VQA-style JSON files and then evaluating different VLMs on temporal grounding, state understanding, planning, viewpoint matching, step ordering, and trajectory prediction.

## Overview

The workflow contains two dataset-generation pipelines:

- `data/time_unders_workflow.py`: generates Time EQA, current-action Understanding, and Left/Right gripper-view matching tasks.
- `data/planning_workflow.py`: generates next-action Planning, goal-conditioned Planning, Step Order, and 2D/3D Trajectory prediction tasks.

The generated JSON files are evaluated by scripts in `test/`, with model calls unified through `test/vlm_api.py`.

## Input Data Format

Both workflow scripts read a directory of `*_segments.json` files. Each file should contain a `segments` list. Each segment must include:

```json
{
  "id": "example_segment_id",
  "start": 1.23,
  "end": 4.56,
  "narration": "pick red cube"
}
```

Optional fields such as `objects`, `main_verbs`, `start_frame`, `end_frame`, `start_time`, and `end_time` are preserved in output metadata.

The video id is inferred from the segment filename by removing `_segments.json`. For example, `episode_001_segments.json` maps to video id `episode_001`.

## Installation

Create a Python environment and install the common dependencies:

```bash
pip install opencv-python numpy pandas requests pillow
```

For local model inference, install the corresponding model dependencies as needed:

```bash
pip install torch torchvision transformers qwen-vl-utils decord
```

Some media-generation paths also require `ffmpeg` to be available in `PATH`.

## Generate VQA Data

Generate Time, Understanding, and Left/Right tasks:

```bash
python data/time_unders_workflow.py \
  --config data/time_unders_workflow_config.json
```

Generate Planning, Step Order, and Trajectory tasks:

```bash
python data/planning_workflow.py \
  --config data/planning_workflow_config.json
```

Useful overrides:

```bash
python data/time_unders_workflow.py \
  --config data/time_unders_workflow_config.json \
  --data-dir /path/to/json_segments \
  --multi-view-video-root /path/to/videos \
  --output-dir /path/to/workflow_outputs/time_understanding \
  --file-limit 10 \
  --no-media
```

`--no-media` generates JSON only and skips frame or video extraction.

## Configuration Notes

Important fields in the generation configs:

- `data_dir`: directory containing `*_segments.json`.
- `video_dir`: single-view video directory.
- `multi_view_video_root`: root directory for per-view videos.
- `views`: mapping from logical view names to video subdirectories.
- `output_dir`: generated VQA output directory.
- `tasks`: task list to generate.
- `category_label_path`: candidate action labels, such as `stack_all_cubes.txt`.
- `num_options`: number of multiple-choice options.
- `use_llm_distractors`: whether to use an LLM to generate distractor options.
- `llm_distractor_api_url`, `llm_distractor_api_key_env`, `llm_distractor_model`: API settings for distractor generation.
- `window_mode`: temporal window mode, one of `raw`, `transition`, or `legacy_pickplace`.

The current planning config uses `glm-5.2` for LLM distractors through `ZAI_API_KEY`. The current time/understanding config uses `gpt-5.5` for LLM distractors through `OPENAI_API_KEY`.

## Evaluate Models

All evaluation scripts support the same core runtime arguments:

```bash
python test/planning_glm_test.py \
  --config test/config_test.json \
  --provider qwen \
  --model Qwen3-VL-32B-Instruct \
  --input /path/to/planning_vqa.json \
  --output /path/to/results.json \
  --limit 10
```

Examples for different tasks:

```bash
python test/time_eqa_glm_test_multi.py --config test/config_test.json --provider glm --model GLM-5V-Turbo
python test/understanding_glm_test.py --config test/config_test.json --provider qwen --model qwen3.7-plus
python test/left_right_glm_test.py --config test/config_test.json --provider internvl --model InternVL3.5-8B
python test/planning_glm_test.py --config test/config_test.json --provider kimi --model Kimi-K2.6
python test/planning_2_glm_test.py --config test/config_test.json --provider gpt --model gpt-5.5
python test/step_order_glm_test.py --config test/config_test.json --provider gemini --model Gemini-3.5-Flash
python test/trajectory_glm_test.py --config test/config_test.json --provider seed --model Seed2.1
```

Use `--overwrite` to recompute existing outputs. For Time EQA, `--limit` limits the number of videos rather than the number of questions.

## API Keys

Set the environment variable for the provider you use:

| Provider | Environment variable | Default API endpoint |
| --- | --- | --- |
| `glm` | `ZHIPUAI_API_KEY` | `https://open.bigmodel.cn/api/paas/v4/chat/completions` |
| `qwen` | `DASHSCOPE_API_KEY` | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` |
| `kimi` | `MOONSHOT_API_KEY` | `https://api.moonshot.cn/v1/chat/completions` |
| `seed` | `ARK_API_KEY` | `https://ark.cn-beijing.volces.com/api/v3/chat/completions` |
| `gemini` | `GEMINI_API_KEY` | configured OpenAI-compatible endpoint |
| `gpt` | `OPENAI_API_KEY` | configured OpenAI-compatible endpoint |
| `internvl` | `INTERNVL_API_KEY` optional | `INTERNVL_API_URL` or `http://localhost:8000/v1/chat/completions` |

For local InternVL inference, use provider `local_internvl_8b` and set `INTERNVL_MODEL_PATH` or pass `--model /path/to/weights`. For local Qwen inference, use provider `local_qwen` and set the model path in `test/config_test.json` or pass `--model /path/to/weights`.

## Output Format

Evaluation scripts write a JSON result file containing:

- `provider` and `model`
- task-level summary metrics
- per-item prompts
- raw model output
- parsed prediction
- ground-truth answer
- correctness or task-specific scores

The prompt sent to the model is saved with each result item, which makes the outputs easier to audit and reproduce.

## Reproducibility Tips

- Keep generated VQA JSON files and evaluation result files under separate output directories.
- Prefer passing `--input` and `--output` explicitly when running from a new machine.
- Update absolute paths in `data/*_config.json` and `test/config_test.json` before running on another server.
- Use `--limit` for smoke tests before full evaluation.
- Record the exact `--provider`, `--model`, config file, and git commit with every benchmark run.
